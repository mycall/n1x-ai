# Model files and storage

For `qwen38fn-best`, place the **W4 target** and **DFlash2 drafter** in separate directories under `ModelRoot`. Setup can prepare the external FP8 PLE table (model embedding data) and cache volumes. The W4/KV19 and W4/KV20 alternatives reuse the same weights and prepared PLE.

Paths below are relative to `ModelRoot`. The [machine-readable W4 inventory](data/model-assets.json) lists every indexed filename, size, metadata hash, and historical profile mapping.

## Required files and volumes

These paths describe the default W4 installation. AZ and native Windows have separate checkpoint requirements below.

| Asset | Exact files / location | Used by |
| --- | --- | --- |
| W4 target weights | `Qwen3.8-Flash-Next-W4A16-AutoRound-hybrid/model-00001-of-00067.safetensors` through `model-00067-of-00067.safetensors`, plus `model_extra_tensors.safetensors`; all 68 files explicitly listed by `model.safetensors.index.json` | W4 profiles |
| Target configuration | Same folder: `config.json`, `generation_config.json`, `quantization_config.json`, `model.safetensors.index.json` | All |
| Text/template files | Same folder: `tokenizer.json`, `tokenizer_config.json`, `chat_template.jinja` | All, including draft tokenization |
| Processor files | Same folder: `preprocessor_config.json`, `processor_config.json` | Preserve for the target's supported multimodal API; text benchmarks do not establish vision quality |
| Target provenance | Same folder: `LICENSE`, `README.md`, `config.json.autoround` | Preserve with the checkpoint; provenance, not additional inference weights |
| DFlash2 checkpoint | `Qwen3.8-Flash-Next-DFlash2/config.json` and `model.safetensors`, mounted at `/drafter` | W4 DFlash2 profiles and AZ DFlash2 profiles |
| MTP checkpoint | Target's `model_extra_tensors.safetensors`: 1,565 `mtp.*` index entries | W4 MTP uses these tensors for drafting |
| FP8 PLE table | Volume `n1x-ple-native`, mounted at `/ple-table-fp8:ro`: `model-00005-of-00131.safetensors` through `model-00037-of-00131.safetensors` (33 files) | W4 MyLLMBox profiles; setup restores missing/incomplete copies from the pinned host source; preserve `n1x-copy-manifest.json` for provenance |
| Prepared PLE map | Volume `n1x-mbx-w4-dflash-test-cache`, `/cache/ple-nvme-fp8/map-c24ea2b9ebbc`, 52,429,053,952 bytes | W4 MyLLMBox profiles; reused when present, generated by the loader on first startup in a new runtime-cache volume |
| LMCache storage | Volume `n1x-c8-lmc4-ssd160-v1`, mounted at `/lmcache`; namespace `qwen-c8-w4-std-fp32-idxbf16-kv11-b4k-v1` | Best and the 88 GiB alternate. The 96 GiB alternatives use profile-specific LMCache volumes |

The selected launcher's installation check requires **all indexed target shards**, including MTP extras even when DFlash2 is selected. Do not remove that file on the assumption that DFlash2 never uses it: changing the checkpoint/index and loader contract would be separate work. Likewise, prepared PLE is model-derived data, not disposable benchmark output. Compiler caches elsewhere in `/cache` are regenerable, but the volume also contains the PLE map.

## Other checkpoints

The Linux AZ profiles use `Qwen3.8-Flash-Next-FP4-Local-AZ` with PLE from that checkpoint and the same DFlash2 drafter. The native Windows reference uses `Qwen3.8-Flash-Next-FP4-Local` and prepares PLE with its external runtime. [AZ revision and verification](FP4-Local-AZ-trial.md#reproducibility-and-scope) · [Native installation](Native-vLLM.md#installation-and-configuration)

Before reclaiming storage, distinguish model weights and prepared PLE from regenerable KV data. Deleting a prompt-cache volume removes its warm entries. Recovering a missing PLE source or map takes additional disk space and preparation time. [Cleanup and disk reclamation](Configuration.md#cleanup-and-disk-reclamation)
